# Factual Seed Pack

Use this before a session to give the model a small set of facts that can be checked or sourced without asking the participant to agree with an interpretation.

For each seed:

## Seed F-___
- **Statement:**
- **Scope:**
- **Source:**
- **As of:**
- **Evidence state:** registered / documented / observed
- **Why it is factual rather than interpretive:**
- **Allowed use:**
- **Sensitivity / handling:**

## Good seed examples
- "Repository `billing-api` exists in the company GitHub organization." Source: repository URL / API result.
- "The published org chart dated 2026-08-01 lists Payments under Commerce Engineering." Source: org chart.
- "The release runbook names `Release Manager` in the approval step." Source: path + section.

## Bad seed examples
- "Payments really owns checkout." (interpretation)
- "Bob is the best engineer." (opinion)
- "Support always bypasses process." (unbounded generalization)
